=====================================================
4. GAME ENGINE ARCHITECTURE (packages/engine)
=====================================================

CORE FILES: packages/engine/src/
├── index.ts      # Public API exports
├── types.ts      # TypeScript type definitions
├── engine.ts     # Game logic implementation
└── share.ts      # Share/export functionality

KEY TYPES:
- LetterMark: "correct" | "present" | "absent"
- GameState: { target, guesses, maxGuesses }
- GuessResult: { feedback, isWin }
- LetterFeedback: { letter, mark }

KEY FUNCTIONS:
- newGame(target, maxGuesses=6): Initialize game
- computeFeedback(guess, target): Calculate letter feedback
- submitGuess(state, guess): Process a guess
- shareGrid(rows): Convert feedback to emoji grid
- shareText(mode, rows, solvedIn?, url?): Generate shareable text

GAME MECHANICS:
- 6 guesses maximum
- Case-insensitive (normalized to uppercase)
- Wordle-style feedback (correct/present/absent)
- Handles duplicate letters correctly (two-pass algorithm)

=====================================================
5. DATA MANAGEMENT & WORDLISTS
=====================================================

WORDLIST STRUCTURE: packages/wordlists/src/

acronyms.json:
- Array of 160+ cybersecurity acronyms
- Each item: { word, expansion, definition }
- Example:
  {
    "word": "CNAPP",
    "expansion": "Cloud-Native Application Protection Platform",
    "definition": "A comprehensive security platform..."
  }

words.json:
- Array of general vocabulary items
- Format: { word, clue } or { word, definition }
- Currently: ~3 items (REACT, VITE, STATE)
- Expandable for additional vocab puzzles

DATA FLOW:
1. JSON files imported via ES modules with JSON assertions
2. Exposed through packages/wordlists/src/index.ts
3. Consumed by:
   - useGameState hook (in memory normalization)
   - LocalListProvider (in-memory word validation)
   - HttpProvider (optional remote source)

NORMALIZATION:
- Words converted to uppercase
- `definition` field fallback: definition ?? clue
- `expansion` field (acronyms only)

SELECTION LOGIC:
- Daily mode: Hash-based seeding (dailySeed function)
- Random mode: Math.random() selection

=====================================================
6. STATE MANAGEMENT & DATA FLOW
=====================================================

CONTEXT/PROVIDERS:

ThemeProvider (apps/web/src/theme/theme.tsx):
- Manages: theme state ("dark" | "light")
- Persists: localStorage("qwizzle:theme")
- Interface: useTheme() => { theme, toggleTheme }

WordProviderProvider (apps/web/src/providers/index.tsx):
- Manages: word provider instance selection
- Routes: HTTP or LocalList based on env vars
- Config: VITE_PROVIDER, VITE_API_BASE env vars
- Interface: useWordProvider() => WordProvider

useGameState Hook (apps/web/src/hooks/useGameState.ts):
- Core game state for current puzzle
- Stats persisted to localStorage("qwizzle:stats")
- Manages:
  * rows: string[] - current and previous guesses
  * cursor: number - current row index
  * feedbackRows: LetterFeedback[][] - guess feedback
  * keyState: Record<string, LetterMark> - keyboard hints
  * message: string - user-facing messages
  * definition/expansion: current puzzle clues
  * gameOver: boolean - game state
  * stats: { played, wins, streak, best, score }
  * result: { outcome, guesses, solution, feedbackRows }

PERSISTED DATA (localStorage):
- "qwizzle:theme" -> theme preference
- "qwizzle:stats" -> GameStats object
- "qwizzle:seen-help" -> help modal flag

EVENT FLOW:
User Input (keyboard/click)
  ↓
GameScreen handler
  ↓
useGameState callbacks (onChar, onBackspace, onEnter)
  ↓
useKeyboard hook (window keydown listener)
  ↓
Board/Keyboard UI update
  ↓
Engine logic (feedback calculation)
  ↓
Stats update + result display

12. ERROR HANDLING
=====================================================

Engine Errors:
- "TARGET_REQUIRED" - missing puzzle target
- "WRONG_LENGTH" - guess not matching word length
- "EMPTY_WORD_LIST" - category has no words

UI Errors:
- "Not enough letters" - incomplete guess
- "Not in list" - guess not in valid words
- Modal error boundary with reload button
- Generic error state in GameScreen

LOCAL STORAGE RESILIENCE:
- Graceful fallback to defaults on read failure
- Console warning on storage failure
- Continues game even if persistence fails
